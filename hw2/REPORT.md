## 1. Задача

Воспроизвести на локальной машине:

1. теоретические соответствия статьи «разреженное внимание ↔ ядерная

2. три набора экспериментов: language modeling на BabiStories (Fig. 2),

контрольные прогоны (§9), итого ~25.

## 2. Суть статьи

Статья устанавливает формальное соответствие между механизмами внимания и
непараметрической ядерной регрессией Надарая-Ватсона (NW):

| Внимание | Ядро NW-регрессии | Полоса (bandwidth) |
|---|---|---|
| softmax (1-entmax) | гауссово | фиксированная, h² = γ |
| sparsemax (2-entmax) | Epanechnikov | **адаптивная**, h = √(2 − 2γτ) |
| 1.5-entmax | biweight (r = 2) | адаптивная |
| 4/3-entmax | triweight (r = 3) | адаптивная |
| normalized ReLU | Epanechnikov | фиксированная (Eq. 6) |
| top-k softmax | усечённое гауссово kNN (Eq. 4/10) | по k ближайшим |
| top-k uniform | равномерное kNN | по k ближайшим |
| r-ReLUmax (новое) | max-anchored полином (Eq. 11) | фикс. отступ от максимума |

**Proposition 1:** α-entmax при α = 1 + 1/r — это NW с ядром
`[1 − ‖u‖²/h²]₊ʳ`, h = √(2 − 2rγτ), где τ — порог α-entmax. Для r = 1, 2, 3
получаем Epanechnikov / biweight / triweight; предел r → ∞ даёт
softmax/гауссово ядро. Нормализованный ReLU — тот же Epanechnikov с фиксированной
полосой (и вырождением 0/0); sparsemax — авто-нормировка (адаптивная полоса);
r-ReLUmax якорится на максимум score и не имеет вырождений (активное множество
эквивалентно {i : kᵢᵀq > m − bh²}, Eq. 12).

Эксперименты проводятся в архитектуре **Memory Mosaics** (ассоциативная память,
явно реализующая оценку Надарая-Ватсона: ключи — усреднённая память прошлого,
значения — со сдвигом на шаг вперёд).

## 3. Реализация

Самодостаточный пакет `hw2/replication/` (см. `README.md`):

* `src/kernels.py` — ядра и активации внимания (sort-based sparsemax, entmax с
  аналитическим якобианом: бисекция порога + `autograd.Function`, r-ReLUmax,
  top-k), оценщик Надарая-Ватсона;
* `src/model.py` — Memory Mosaics: перенос архитектуры
  (`deep-spin/sparse_kernel_regression`, Library/models) на чистом PyTorch;
* `src/data_synthetic.py` — генераторы MQMTAR/Reverse/Sort и перенос метрик
  из официального `test_synthetic.py`;
* `src/icl_dfa.py` — протокол RegBench из `berlino/seq_icl` (генерация PFA,
  разделение train/val/test по PFA, метрики dfa-accuracy и TVD);
* `src/train_*.py` — тренировочные скрипты с логированием прогресса и
  сохранением `metrics.json`;
* `src/analyze.py` — сведение результатов в таблицы и графики.

Официальный код статьи непригоден к запуску как есть (отсутствует `utils.py`,
рассинхронизированы импорты `common_metrics_epoch1`, зависимость от
adasplash/triton, синтетические данные не выложены). Модель и пайплайны
перенесены чистой реализацией с той же семантикой; соответствие форматов
данных и метрик проверено по официальному коду.

## 10. Примечания к реализации

1. **Подготовка BabiStories.** Токенизация выполняется потоковой записью
   (память O(1)); `train.bin`/`val.bin` сверены с Table 4 статьи
   (474 704 907 / 4 749 107 токенов — точное совпадение).
2. **Детали реализации.** Соответствие официальному коду и статье:
   causal-маска исключает главную диагональ (суммы внимания идут до n−1);
   замаскированные ключи исключаются явной маской, недопустимые score (−inf)
   заменяются на −1e9 перед sparsemax/entmax ради числовой устойчивости;
   backward постоянной памяти чанкуется по batch; в ICL метки −100
   исключаются через `ignore_index`.
3. **Синтетические данные.** Авторами не выложены; генераторы реализованы по
   Appendix B.3, формат ответа MQMTAR восстановлен из официального eval-кода
   (позиции пар в ответе: 1,2, 4,5, 7,8, 10,11).
4. **Загрузка LM-датасета.** `MemmapChunks.batch()` семплирует случайные
   чанки напрямую из memmap (память O(batch)), как в официальном
   `InfiniteDataLoader` с `RandomSampler(replacement=True)`; валидация на
   полном датасете — потребление ~1 ГБ RAM.
5. **normReLU/ReLUmax в официальном коде.** Параметризация не совпадает с
   Eq. 6/11 буквально: в `Library/models/memory_mosaics.py` score уже содержит
   β² (ключи умножаются на β до скалярного произведения) и дополнительно
   делится на γ = h²/2 при h = 1/β — эффективно коэффициент при cos становится
   2β⁴ вместо 2β² из Eq. 6; наш порт повторяет эту семантику. В
   `memory_mosaics_eft.py` у norm_relu параметры γ и b вычисляются, но не
   входят в формулу — фактически normalize(ReLU(k·q)). Учитывать при
   сопоставлении normReLU со статьёй.
